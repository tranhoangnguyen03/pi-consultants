# Map journeys and needs from evidence

Choose the scope: one user group, one goal, start and end. Build the map from evidence: research, support conversations, analytics paths and your own walkthrough, each marked by source. Show stages, user actions, thoughts and feelings, touchpoints, pain points and opportunities; add the backstage services and systems (service blueprint) when the problem crosses teams. Frame needs as jobs to be done: the situation, the motivation and the outcome people want, not features. Build personas only when real segments differ in goals or behaviour, from evidence, without invented demographics. Mark assumptions and gaps visibly. Render maps with the diagram-design skill so they are shareable. End with the few moments that matter most and what to do about them; a map that changes no decision is decoration.

## Working contract
Use the general consultation entry point in AGENTS.md. This is a method, not a compulsory workflow. Combine it with another method only when that improves the requested outcome. Respect review versus revision authority. Check the current case and retain only material findings, decisions and open questions. Report actual evidence and limitations.

# Review and revise technical documentation

Identify intended readers and the tasks the document should enable. Verify claims against code, configuration and the target revision. Run safe examples and installation commands in a clean environment where possible. Check prerequisites, defaults, failure messages and recovery instructions. Separate tutorial flow from reference detail and preserve important qualifiers. Remove duplicate or stale guidance only after preserving its useful content. Mark untested platform or integration instructions explicitly. For a final clarity pass on consequential tool descriptions, agent instructions, or error and recovery procedures, the optional engineering-asd-ste100 method can help. Keep modality and evidence state, and when revising existing text, list the changed sentences and flag any possible change in meaning. Do not apply it to ordinary replies, reviews or case notes unless the wording is the problem. Coordinate audience-facing delivery with C when needed; accuracy and usability remain B's responsibilities.

## Working contract
Use the general consultation entry point in AGENTS.md. This is a method, not a compulsory workflow. Combine it with another method only when that improves the requested outcome. Respect review versus revision authority. Check the current case and retain only material findings, decisions and open questions. Report actual evidence and limitations.

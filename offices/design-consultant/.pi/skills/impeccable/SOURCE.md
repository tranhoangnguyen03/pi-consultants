# Impeccable integration provenance and scope

- Upstream: https://github.com/pbakaus/impeccable
- Publisher: Paul Bakaus and contributors
- License: Apache-2.0, https://github.com/pbakaus/impeccable/blob/main/LICENSE
- Evaluated pin: npm `impeccable@4.7.0`; platform engine `0.1.16` (upstream's optional dependencies).
- This office ships an original narrow Node adapter and original guidance, not the upstream skill tree or binary. Exact CLI and engine binaries download on first use.
- The adapter source `scripts/impeccable.mjs` owns the pin and disabled-telemetry flags; upgrades require review and a new test.

Intentional changes: HQ case papers, notes and briefs hold consultant memory; not upstream `PRODUCT.md`, `DESIGN.md`, `.impeccable/critique`. No mandatory direction choices, critique subagents, Pi hooks or extra permission during authorized local work. Only upstream `detect` is used in this first stage. F's browser tools drive actual UI inspection and iteration. Upstream `live` and `generate` require a separate Pi and state-safety check.

The detector can fetch an explicit remote URL and may download a platform binary into private HQ tools. Anonymous telemetry is switched off. The upstream visual-world roll API is not called by this adapter. A clean detector report cannot certify design quality or release acceptance.

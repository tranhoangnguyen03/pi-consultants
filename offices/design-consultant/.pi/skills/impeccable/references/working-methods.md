# Impeccable-inspired design tactics for Consultant F

These are **agent-selected tactics**, not commands the user must learn or gates that pause work. Use one or two that fit the task, working from actual product content and constraints. Keep durable decisions in the current HQ case, not an Impeccable project workspace.

| Need | Tactic | Observable result |
|---|---|---|
| Fresh or unclear structure | **Shape:** define the main task, object and action, consider alternatives, choose one | A screen whose hierarchy supports the task |
| Weak visual character | **Bolder:** strengthen one meaningful visual feature | A specific, legible visual direction |
| Overstimulating interface | **Quieter:** reduce competing accents and motion | Clearer task focus |
| Too much UI chrome | **Distill:** cut or combine nonessential elements | Less distraction without lost actions |
| Final visual gaps | **Polish:** align type, spacing, copy, states and breakpoints | Inspected rendered result |
| Failure and edge cases | **Harden:** handle missing, slow, long, translated and error content | Usable fallback and recovery |
| Different devices | **Adapt:** inspect narrow, medium, wide and input methods | No blocked actions or overflow |
| Vague labels | **Clarify:** use the project's verbs for actions and recovery | Understandable controls and errors |
| Meaningful feedback | **Animate:** show state changes, respect reduced motion | Motion that helps rather than distracts |
| UI performance | **Optimize:** measure, then fix consequential regressions | Before/after evidence |

Run the bundled pinned detector with `node <F-HQ>/.pi/skills/impeccable/scripts/impeccable.mjs detect <project> <target>` as supporting evidence. Resolve false positives against product context. It is not the quality gate.

Do not force a direction ballot, critique interview or separate agent workflow. Choose, work and verify independently; the user has control at the substantial **quality gate** and **delivery gate**.

# Learn from the completed assignment

Adapted from Paperthin. See ../readchk/NOTICE.md for attribution.

## Use
After a substantial delivered, failed, disputed, or disappointing work cycle when the outcome offers a reusable lesson. Skip trivial exchanges.

## Method
1. Review the objective, delivered work, observed results, QA evidence, user feedback, and existing case notes.
2. Distinguish proven results from unverified claims and activity that only looked productive.
3. Group repeated failures into general patterns. Retain concrete examples as evidence, not universal rules.
4. Identify lessons, harmful patterns, and the cheapest check that would catch the problem next time.
5. Record only meaningful findings via hq_note in this office's selected case/engagement, with the required scope, attribution, evidence, and uncertainty. Update the brief only as warranted.
6. Use supersession to update outdated conclusions without deleting case history.

## Limits
Do not access another office's private notes. Do not create a second memo database, task tracker, knowledge server, or Git publication step. Firm-wide collection and review remain separate Knowledge Office duties. Recording lessons is not acceptance or engagement closure.

## Result
Short account of outcomes, evidence-backed lessons, failure patterns, future checks, and open questions. If nothing useful was learned, record nothing.

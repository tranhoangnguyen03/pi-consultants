# Consultant HQ

Install your organization's shared playbook as `organization/PLAYBOOK.md` (from the firm repository: `npm run setup -- --playbook FILE`, or `cp organization/PLAYBOOK.example.md organization/PLAYBOOK.md` and edit it). Rules for this consultant only go in `organization/PLAYBOOK.local.md`; the shared playbook wins on conflict. Run `cd <HQ> && pi` with compatible Pi/Node and normal authentication. The bundled runtime needs no firm checkout. Private .hq/, .env and local configuration must travel separately from git. Configure with `node .runtime/bin/hq.mjs configure --root /path/to/HQ --projects /path/to/project`. Check prerequisites with `node .runtime/bin/hq.mjs doctor`: it lists missing software and how to install it. Every office ships the same toolset (`.pi/toolset.json`): Pi packages install on first start; account connectors start switched off. Enable one with `node .runtime/bin/hq.mjs configure --connect NAME`, then sign in with `/mcp` inside Pi. The bundled CLI infers its HQ location; --root is optional. The pinned directory package declares Node >=24.15.0; doctor checks declared prerequisites, not actual startup or model quality.

Updates: close Pi sessions in this office, then run `npm run setup` from the firm repository. Offices inside the repository update with `git pull`: inspect Git status and preserve local edits first; Git does not use setup backups. `--rebuild` regenerates shipped offices from `firm/`, and `--out DIR` updates offices built elsewhere. Inspect `--status` before updates. Setup preserves private state and local configuration; a conflict stops replacement for that office, not the whole batch. Review conflicts before `--force`, which backs them up into .hq/setup-backup/ before replacement. No automatic updates or state migration. The kit source runbook at firm/docs/OFFICE-ADMIN.md documents imports, legacy-case upgrades and recovery; it is not bundled into this independent office.

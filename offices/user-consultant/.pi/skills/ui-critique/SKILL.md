# Critique interface design against what users need to do

Review the real rendered UI and, when available, the design source (Figma connector) side by side. Judge each screen by its job: is the primary action obvious, is the most important information first, does the layout guide the eye in task order? Check visual hierarchy, grouping and spacing, alignment, typography scale, colour use and contrast, iconography with labels, affordances, states (hover, focus, disabled, selected, error) and responsive behaviour. Check consistency with the product's own patterns and design system before suggesting new ones. Tie every comment to a user consequence, such as missed action, misread state, slower scanning or lost trust; mark pure taste as taste. Propose concrete alternatives, sketched as annotated screenshots or simple diagrams when words are not enough. Prefer fixing the system or component over one-off patches.

## Working contract
Use the general consultation entry point in AGENTS.md. This is a method, not a compulsory workflow. Combine it with another method only when that improves the requested outcome. Respect review versus revision authority. Check the current case and retain only material findings, decisions and open questions. Report actual evidence and limitations.

# Evaluate whether people can complete their tasks

Pick representative tasks from real user goals, with realistic starting knowledge and data. Walk each task through the actual interface with the browser, including first use, returning use, errors, empty and loading states, interruptions, small screens and slow connections. Record each friction point at discovery, comprehension, input, feedback, completion and recovery, with a screenshot and where it happens. Use established heuristics (visibility of status, match to real-world language, user control, consistency, error prevention and recovery, recognition over recall) to explain why something fails, not as a checklist. Rate each issue by severity and reach, and separate blockers, friction and polish. When the stakes justify it, plan a test with real participants: tasks, success criteria, observation notes, and a moderator guide that does not lead. Where agents use the same flow, run them through it too (see agent-experience). Always label whether a finding comes from your walkthrough, observed users or observed agents.

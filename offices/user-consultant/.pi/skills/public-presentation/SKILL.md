# Judge the first public impression

Review the page a newcomer actually lands on, in the order they see it: the About text and topics, the first screen of the README, the install and first-run path, then the package page. Ask whether a stranger can tell in ten seconds what the product does for them, trust what it touches, and get a first success. Check the live page and its rendering, not only the files, and mark what you could not view. Read references/principles.md in this skill's folder for the rules and the gap-list format, and references/platforms.md in this skill's folder before citing any platform field, limit or behaviour; recheck those against the live platform. Its Pi section applies only to packages with the pi-package keyword. Rank gaps MUST, SHOULD or NICE with the evidence and the exact proposed text. Flag CI, supply-chain, branch and repository-settings items as present or missing without judging them. Include "For B (engineering)" or "For C (coordination)" sections only when findings need their attention; these are paste-ready guidance, not a mandatory handoff. Read references/demo-recording.md in this skill's folder only when the user wants a demo recording produced. For agents that install from these pages, combine with user-agent-experience.

Follow the shared practice in AGENTS.md; use this method only when it helps the task.

# Judge the first public impression

Review the page a newcomer actually lands on, in the order they see it: the About text and topics, the first screen of the README, the install and first-run path, then the package page. Ask whether a stranger can tell in ten seconds what the product does for them, trust what it touches, and get a first success. Check the live page and its rendering, not only the files, and mark what you could not view. Read references/principles.md for the rules and the gap-list format, and references/platforms.md before citing any platform field, limit or behaviour; recheck those against the live platform. Its pi-family section applies only to pi-* repositories. Rank gaps MUST, SHOULD or NICE with the evidence and the exact proposed text. Flag CI, supply-chain, branch and repository-settings items as present or missing without judging them, and end with "For B" and "For C" sections the user can paste to those consultants. Read references/demo-recording.md only when the user wants a demo recording produced. For agents that install from these pages, combine with user-agent-experience.

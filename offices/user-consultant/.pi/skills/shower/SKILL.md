# Cold-read an important handoff

Adapted from Paperthin. See ../readchk/NOTICE.md for attribution.

## Use
Before consequential handoff, publication, or implementation from a design. Not required for each small edit.

## Method
1. Identify the artifact and its intended reader. Keep the author's interpretation private from the reviewer.
2. If an already-available, authorized isolated reviewer can inspect it, give that reviewer only the artifact contents, not the earlier conversation or neighboring project notes. Do not install agents or create or message sessions just to run this method.
3. Ask what the artifact means, what action it enables, where it is unclear, and what the reader had to guess.
4. Compare the blind reading with the actual intent. Report blocking gaps and precise repairs. Fix in the authoring session.
5. If a genuine fresh reviewer is unavailable, say "Independent cold-read not run." A limited same-session review is fine but must not be described as independent.

## Limits
Respect client confidentiality and office case boundaries. A clear document is not proof of correctness or approval. Do not invoke the human-steered parallel-branches workflow automatically.

## Result
Verdict, important assumptions, recommended fixes, and whether independent review actually ran.

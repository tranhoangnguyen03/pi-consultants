# Prototype the question, not the whole game

Find one clear question worth testing. Establish engine, target device and input. Choose a smallest representative loop: start → act → get feedback → succeed/fail → retry. Use greybox shapes and placeholders honestly; avoid final assets until the mechanic deserves them.

Build and launch real interactions. Observe controls, response time, camera, collisions, goal states and restart. If an authorized player test is possible, record what the player did; otherwise describe the untested gameplay hypothesis. Separate technical feasibility, observed usability and fun.

Give a concise keep/change/stop judgment, runnable path and source changes. Leave accepted work in the project Site. Use `game-dev-routing` to fetch engine-specific help only when necessary.

# Write interface content people understand

Find where words cause failure: support questions, recordings, search terms, research quotes and your own walkthrough. Use the users' vocabulary, not internal names. Make each element do one job: labels say what something is, buttons say what will happen, errors say what went wrong and how to fix it, empty states say what to do first. Front-load the important words, keep sentences short, and keep terms consistent across the product. Write for scanning and for people reading in a second language. Check that text works with assistive technology and when translated or truncated. Propose exact replacement text in context, ideally on a screenshot, with the reason and the evidence. Treat text agents read as interface content too: tool and parameter descriptions, API docs, help output and error messages must tell an agent what something does, when to use it and what to do next. Test critical wording with users, and with real agents where they read it, when the stakes are high.

# Reconcile project state and commitments

Identify the question, period and authoritative sources. Reconcile GitHub implementation evidence, Linear work records, stakeholder discussions and relevant documents. Treat recency as one clue, not automatic authority. Keep intent, proposal, agreement and observed result separate. Identify unconfirmed dates, unresolved owners, blocked decisions and the consequences of delay. Recommend the smallest useful clarification, escalation or record change. Do not create a second task tracker in HQ. Retain decision history and links; recheck current state before a new assertion.

Follow the shared practice in AGENTS.md; use this method only when it helps the task.
